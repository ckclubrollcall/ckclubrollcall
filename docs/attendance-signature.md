# 重新簽名與檔案智慧方塊：部署及驗收

本分支採分批提交；前後端接線與全部測試完成前，不可部署中間版本。

## 資料與角色

- 新增點名使用老師簽名；修改歷史紀錄使用修改者簽名。
- 點名紀錄保留既有「老師簽名」欄名，以「紀錄類別」區分新增／編輯；報表必須顯示正確角色。
- 紀錄採附加新列，保留原紀錄與簽名檔案。歷史空白類別不會全部回填為新增。
- 同社團、同社課日期以提交時間較新者為準；時間相同以較後列為準。
- 簽名智慧方塊是檔案預覽入口，不是儲存格內嵌圖片。不可用 HYPERLINK 或 IMAGE 代替。

## 部署前置

1. 先備份試算表與 Apps Script，在測試副本驗證，不直接修改正式資料。
2. 複製全部 gas 檔案，包含新增 attendance_store.js；使用更新的 appsscript.json 啟用 Sheets v4 進階服務。
3. 若使用標準 Google Cloud 專案，另外啟用 Google Sheets API；以部署者身分重新授權並建立新版部署。
4. 從「簽名報表」選單執行「初始化／檢查點名紀錄欄位」。缺少「紀錄類別」時附加於末端；其他必要欄名缺失或重複會停止，請依 ATTENDANCE_FIELDS 對照確認，不猜測欄位位置。
5. 保持原本的 Drive 資料夾權限，不新增公開分享。B1 為簽名資料夾，B2 為報表資料夾。
6. 後端、前端需協調更新；不可讓舊前端持續送出 KEEP。

## 統計總表相容性

簽名報表以欄名取得社團編號、社團名稱與指導老師，不再依賴教師固定為第八欄。因此插入「最新的簽名圖片」「最後修改日期」不會讓教師讀取錯位。

儲存庫未提供正式試算表內既有公式，不應臆造或覆寫它們。本次不自動重建統計總表、插入兩欄或清空既有公式。管理員需依總表的實際列粒度設定這兩欄：若每列是一個社團，最新為該社團提交時間最新一筆；若另有指定社課日期，先依日期篩選。最後修改日期指提交時間，不是社課日期。

既有公式若把「老師簽名」當裸網址使用，必須另外調整：智慧方塊的顯示文字不保證是真實 URI；應由 Sheets API chipRuns 取得檔案 URI。只插入欄位與公式繼續正確運作，是兩項不同的驗收工作。若要顯示內嵌圖片，不可為了 IMAGE 公式把私人簽名改成公開分享。

## 測試

使用 Node.js 內建測試工具：

```sh
node --test tests/attendance-store.test.cjs
node --check gas/attendance_store.js
node --check gas/sign.js
node --check gas/setting.js
```

Mock／單元測試不能代替真實 Apps Script、Sheets、Drive 整合驗證。正式部署前在副本確認：新增與編輯角色、未簽名拒絕、智慧方塊可預覽、歷史連結可讀、欄位重排、總表插欄、私人簽名報表、逾時與失敗提示。

## 安全性與限制

PNG 驗證限制編碼與解碼後大小、檔頭、尺寸、區塊邊界及 CRC；不是完整圖片解碼器，不證明筆畫非空、真人身分或圖片一定為剛剛手寫。伺服器不可接受 KEEP 或任意簽名 URL，也不可依前端旗標決定權限與紀錄類別。

Sheets 同次 batchUpdate 寫入資料與智慧方塊，但 Drive 與 Sheets 沒有跨服務交易。送出前失敗只清理本次新檔；送出後逾時先核對檔案 ID，無法確認時保留檔案、不誤報成功，請管理員核對後再重試。可能留下待清理檔案；不要自動刪除歷史簽名。

報表只讀取指定簽名資料夾內、大小受限的 PNG；不因試算表內的任意 URL 而將其他私人檔案嵌入報表。新增報表不刪除同名歷史報表。
