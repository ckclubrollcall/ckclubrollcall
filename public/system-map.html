建中社團點名系統 — 系統導覽與架構

互動式運作說明與系統流程圖 — 提供基本運作與完整技術架構雙視圖

[流程] 系統基本運作邏輯

整套系統是如何跑起來的？

系統核心目的，為將紙本點名過程，以電子化、自動化方式替代，減輕學務處社團活動組及社長的行政負擔。
整套運作主要分為三個極簡步驟：

步驟一
幹部用手機開啟網頁，填寫點名與手寫簽名
社團幹部打開瀏覽器登入學校 Google 帳號後，系統會自動載入該社團最新社員名單。幹部勾選出席狀況，並請指導老師直接在手機螢幕上進行手寫數位簽名。
步驟二
Google 雲端（GAS）自動接單與安全核對
按下「確認送出」後，資料會經由安全傳輸管道送往託管於 Google 的後台（Google Apps Script）。後台會自動進行安全防護檢查（如確認是否有漏填、是否有惡意字元、帳號冷卻時間等），確認無誤後將老師簽名妥善儲存至 Google 雲端硬碟。
步驟三
雲端試算表自動記帳，即時統計並產生報表
資料寫入 Google 試算表後，公式自動計算當天全校缺席名冊、各社團出席率與老師到課統計；學務處或管理者亦可透過選單一鍵將所有簽名匯出成 Google Doc 文件。
[維護] 系統修復維護與建立工作小組

系統出了問題如何處理？

為確保系統穩定運作，我們建立了工作小組： 工作小組脫離建中班聯會體系增加效率，老師可以隨時私訊成員回答問題，並由工作小組成員協助維護系統。 本小組每年將招募新學弟作為組員，避免畢業後難以維護的問題(詳細小組章程將於日後向老師說明)。

[效益] 系統實施效益

系統實施後帶來哪些效益？

本系統的導入為學校社活組老師與全校社團帶來實質且顯著的行政與運作效率提升：

一、 社活組老師大幅減少工作量

收發點名表與學生奔波

傳統做法：需人工發放與回收紙本點名表，學生與幹部頻繁往返學務處。

➔ 改為：完全線上進行，隨開隨填，零紙本零跑腿。

未繳交社團與缺席核對

傳統做法：老師需手動逐份對照紙本點名表，確認哪些社團沒交、哪些學生缺席。

➔ 改為：系統秒級自動整理報表，即時呈現未交社團與全校缺席名冊。

老師簽名與薪水清冊統計

傳統做法：逐一核對指導老師紙本簽名、手動計算各社團老師鐘點費與薪水。

➔ 改為：系統自動彙整到課資料與數位簽名，老師僅需輸入數值即可精確計算。

二、 社團提升運作效率

幹部點名與領取表單

傳統做法：每次社課都需要特別指派一名幹部專程來回學務處領取與繳回點名表。

➔ 改為：只要手機點開網頁連結即可即時完成點名與老師手寫簽名。

學生出缺席狀況確認

傳統做法：學生不確定自己累積幾次出席/缺席，需特地詢問幹部或跑學務處查詢。

➔ 改為：學生可以直接登入系統，隨時線上查看個人出缺席歷史紀錄。

[資安評估] 個資保護與防護措施

系統如何保障個資與防止點名資料被竄改？

本系統特別針對校園點名場景設計多重防護機制，從基礎架構到資料寫入皆有嚴格控制：

[架構資安] Google 級基礎設施託管

全系統的後台邏輯（GAS）、資料庫（Google 試算表）與簽名檔存儲（Google Drive）皆完全託管於 Google 雲端官方基礎架構。

  • 安全性等於 Google 表單：無須維護私設伺服器，資安標準與 Google 帳號同級。
  • 傳輸全程加密：所有請求傳輸均使用 HTTPS 標準 TLS 加密。

[身分與個資] 身分隔離與個資保護

徹底實施最小權限原則，嚴格保護學生隱私與存取權限。

  • 最小化個資：僅使用學校官方學號與姓名比對，不讀取不必要的私密隱私（如手機、地址）。
  • 社員權限隔離：一般社員登入後僅能「查詢個人出缺席紀錄」，無法檢視他人資料或進行點名與修改。

[防竄改] 數位簽章與軌跡留存

防止點名資料被未授權修改、冒簽或洗刷。

  • HMAC 數位簽章：提交請求經過 HMAC-SHA256 加密憑證驗證，防範偽造數據。
  • 修改保留歷史列：修改紀錄採「新增列」方式寫入，不直接覆蓋舊資料，保留完整異動日誌。
  • 5 天維護期限：超過 5 天前的點名紀錄自動鎖定，不可任意變更。

[防攻防刷] 惡意腳本與冷卻機制

針對網頁與試算表 common 攻擊進行主動防範。

  • XSS 腳本過濾：所有輸入欄位均過濾 HTML 標籤與不可見控制字元。
  • 公式注入防護：自動對試算表敏感符號進行轉義 (`\u200B`)，防止惡意執行注入指令。
  • 60 秒冷卻防刷：同一帳號提交設有 60 秒頻率限制，防止惡意洗刷資料。

系統總覽
整個系統由三大部分組成：使用者看到的前台網頁、處理邏輯的後台伺服器 (Google Apps Script)、以及儲存資料的 Google 雲端與試算表。

前台網頁

使用者直接操作的介面，包含登入、填寫點名表、簽名、查詢紀錄等畫面。
檔案位置：index.html + style.css + app.js

後台伺服器 (GAS)

Google Apps Script 部署在雲端，負責身分驗證、資料讀寫、安全防護。所有前台請求都經由它處理。
檔案位置：Google 試算表 GAS 內建 (form.js)

Google 雲端儲存

Google 試算表存放學生名單、點名紀錄；Google Drive 資料夾儲存老師手寫簽名圖檔與簽名報表。
檔案位置：Google 試算表與 Google Drive

安全機制

多層防護：Google Token 驗證、HMAC 加密簽章、60 秒冷卻防刷、XSS 防護、公式注入阻擋、權限隔離。
檔案位置：form.js ➔ SECURITY 規格與安檢函式

試算表結構（底層 + 公式 + 報表）

底層資料：原始名單、點名紀錄、系統設定、系統日誌
公式彙整：原始社團、統計總表、當日缺曠、校內/校外出席老師紀錄
互動報表：查詢面板
檔案位置：Google 試算表工作表與內建公式

使用者身分

幹部：可「開始點名」+「查詢紀錄」+「修改紀錄」
社員：只能查自己的出缺席
測試帳號：外部人員用密碼登入
檔案位置：app.js / form.js 權限對照

前後台溝通完整路徑
前台每一個操作，都會透過 HTTP POST 呼叫後台的 API 路由器。後台驗證身分後，對 Google 試算表進行讀取或寫入，再將結果回傳給前台顯示。

試算表公式與完整使用
前台與 GAS 只負責寫入原始資料；真正把資料整理成客戶可閱讀報表的，是試算表中的公式層。整份試算表可以理解成「底層資料 ➔ 公式彙整 ➔ 報表輸出」三層。

底層資料表

原始名單：班級、座號、姓名、學號、身分、社團編號、社團名稱。
點名紀錄：每次送出的正式點名資料。
系統設定：簽名/報表資料夾、測試帳號。
系統日誌：錯誤追蹤。
Google 試算表工作表

公式彙整表

主要使用 LET、ARRAYFORMULA、MAP、FILTER、XLOOKUP、VLOOKUP、HSTACK 等函數，把點名原始資料自動整理成管理報表。
Google 試算表內建公式

輸出工具

查詢面板：選社團後，由 club_search.js 自動畫出全學期矩陣、缺席明細、社課摘要。
簽名報表：由 sign.js 匯出成 Google 文件。
Google 試算表 GAS 腳本

客戶操作順序

1. 維護「原始名單」與「系統設定」
2. 從前台網頁送出點名，資料進入「點名紀錄」
3. 透過公式表看當日統計與缺曠
4. 用「查詢面板」查整學期，用選單產出簽名報表

▸

「原始社團」公式：自動建立社團清單
公式位置：A2；用途是從原始名單長出社團主表
公式層
▸
主公式：LET + SORT + UNIQUE + FILTER + MAP
從「原始名單」的社團編號與社團名稱欄位抓出所有不重複社團，並自動排序。

自動計算每個社團應到人數

公式位置：Google 試算表「原始社團」工作表 D 欄
這張表是後面所有報表的社團字典
「統計總表」與老師出席統計都會先讀這張表，因此新社團只要出現在原始名單，這裡就會自動長出來。
位置：Google 試算表 ➔「原始社團」工作表
客戶實際使用方式
平常不需要手動改 A2 公式欄；只要更新「原始名單」即可。若右側另有老師、校內/校外、統計標記欄位，則依學校管理需求人工維護。
操作指引：只需維護「原始名單」
「統計總表」公式：看當天哪個社團已繳交
公式位置：A2；核心是把社團主檔與點名紀錄依日期對起來
公式層
▸
查詢日期來源：I3
這張表的公式會先讀 I3 的日期，作為「今天要檢查哪一天的點名狀況」的目標日期。
位置：Google 試算表「統計總表」工作表 I3 儲存格
主公式：LET + FILTER + MAP + XLOOKUP + HSTACK
先從「原始社團」抓社團編號、名稱、應到人數，再從「點名紀錄」組出「社團_日期」鍵值，找出每個社團該日最新一筆提交。
公式位置：Google 試算表「統計總表」工作表 A2 儲存格
產出欄位
公式會輸出社團編號、社團名稱、是否已繳交、最後填寫人、應到人數、實到人數、出席率，讓管理者一眼看完當日狀況。
位置：Google 試算表「統計總表」工作表 A2:G 欄
若同一天有修改紀錄，只取最新那筆
因為公式使用最後匹配邏輯，所以幹部後續修改資料時，總表會自動反映最新提交結果，不需要人工刪舊資料。
公式機制：最後匹配最新提交列
客戶實際使用方式
每日只要改一次 I3 的日期，就能立即看到「哪些社團已交、誰填的、實到多少人」。這張表也是簽名報表建立社團對照時的重要來源。
操作指引：每日更改 I3 日期
「當日缺曠」公式：自動整理全校當天缺席名單
公式位置：B5；把各社團缺席名單展平成可追蹤的學生清冊
公式層
▸
查詢日期來源：C2
先在 C2 指定要查詢的社課日期，公式就會從「點名紀錄」篩出當天資料。
位置：Google 試算表「當日缺曠」工作表 C2 儲存格
主公式：FILTER + SORT + UNIQUE 邏輯 + TEXTJOIN + SPLIT + TOCOL
先取出每個社團當天最新一筆，再把所有缺席名單合併、拆行、清理空白，變成一列一位學生的資料。
公式位置：Google 試算表「當日缺曠」工作表 B5 儲存格

公式會把「班級_座號_姓名」再回查「原始名單」，補出正式學號，最後輸出班、座、名、學號四欄。
公式位置：Google 試算表「當日缺曠」工作表內建 VLOOKUP
自動排除全勤與空白資料
若某社團標示為「全勤」或當天尚未有缺席資料，公式不會把它列進結果，所以這張表直接可拿來做當日缺席名冊。
公式機制：自動排空與全勤
客戶實際使用方式
每天只需改 C2 的日期，就能得到全校跨社團的缺席學生清單，適合值班老師、學務單位或後續通知使用。
操作指引：每日更改 C2 日期
「校內 / 校外出席老師紀錄」公式：自動算老師出席統計
公式位置：A2；以社團分類欄位與點名資料自動生成老師端報表
公式層
▸
資料來源
公式會讀取「原始社團」中的社團、老師與分類欄位，再對照「點名紀錄」中的老師是否出席（G 欄）與代課老師（H 欄）。
位置：Google 試算表「原始社團」與「點名紀錄」
主公式：ARRAYFORMULA + FILTER + SORT + MAP + UNIQUE + VSTACK
先把同一社團同一天的舊紀錄排除，只保留最新結果，再統計每位老師的應到次數、請假次數與實到次數。
公式位置：Google 試算表「校內出席老師紀錄」與「校外出席老師紀錄」A2 儲存格
校內表會額外把代課老師獨立列出
若社團被設定為需要計入代課統計，且當次老師請假，公式會把代課老師另外整理成單獨列，方便核對實際授課情況。
位置：Google 試算表「校內出席老師紀錄」工作表
校外表則專注於校外社團
校外社團使用獨立統計表，讓校內、校外兩種管理口徑不會混在一起。
位置：Google 試算表「校外出席老師紀錄」工作表
客戶實際使用方式
這兩張表適合學期末彙整老師到課狀況、代課次數與請假統計；平常不需要手動重算，更新點名資料後會自動刷新。
操作指引：自動刷新不需手動重算
